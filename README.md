# 집중 타이머

Windows 10/11 x64용 단일 작업 타이머입니다. Windows 앱 색 모드에 맞춰 라이트·다크 테마를 자동 적용합니다.

숫자, 한글, 버튼, 설정, 알림, 툴팁에는 [Pretendard v1.3.9](https://github.com/orioncactus/pretendard/tree/v1.3.9)를 사용합니다. Regular·SemiBold·Bold 글꼴을 앱에 포함하여 별도 폰트 설치가 필요 없습니다. 기능 아이콘은 Segoe Fluent Icons를 사용합니다. Pretendard 저작권 고지와 SIL Open Font License는 실행 파일에 포함되며 **설정 → 라이선스**에서 읽을 수 있습니다.

## 실행

`dist/FocusTimer.exe` 하나만 복사해 실행하세요. .NET과 글꼴이 포함되어 별도 설치가 필요 없습니다. 실행에 필요한 내부 파일은 첫 실행 시 임시 캐시에 자동으로 풀립니다.

- 원 안의 시·분·초 숫자를 클릭해 직접 입력하고 **시작**을 누릅니다. 각 칸은 숫자 두 자리만 입력되며 시는 00–99, 분·초는 00–59입니다. 한 자리 입력은 편집을 마치면 두 자리로 맞춰집니다. 실행 중에는 읽기 전용이며 **일시정지** 후 편집할 수 있습니다.
- **다음 정시**는 다음 `HH:00`, **다음 30분**은 다음 `HH:30`까지 즉시 시작합니다. 예를 들어 14:10에는 14:30까지, 14:40에는 15:30까지 설정됩니다. 정확히 14:30에 누르면 15:30이 목표입니다. 실행 중 누르면 현재 타이머를 교체합니다.
- 우측 상단의 **소형 모드** 버튼으로 작게 표시합니다. 가장자리로 120×40까지 줄이고 빈 영역을 끌어 이동하세요.
- 기본·소형 모드 모두 화면 가장자리나 모서리로 끌어도 Windows 자동 분할 배치를 시작하지 않습니다. 직접 이동과 가장자리 크기 조절은 그대로 사용할 수 있습니다.
- 소형 창에 마우스를 올리거나 `Tab`을 누르면 조작 버튼이 나타납니다. 핀 버튼으로 항상 위 표시를 해제할 수 있습니다. 160×64보다 작게 줄이면 시간 대신 시작·일시정지, 핀, 기본 크기 버튼 3개만 나타납니다.
- **설정**에서 배경 불투명도와 무음 완료 팝업을 조절합니다. 숫자·원형 바·버튼·아이콘·테두리는 배경이 투명해지는 정도의 절반만 투명해집니다(배경 불투명도 50% → 전경 75%, 배경 10% → 전경 55%).
- **리퀴드 글래스**를 켜면 소형 창이 캡슐형 유리로 바뀝니다. 중앙은 맑게 유지하고 가장자리에는 실제 뒤 화면의 굴절과 얇은 빛 반사를 적용합니다. Windows 11 이상에서 지원하며 라이트·다크 테마를 따릅니다. 효과가 실제로 활성화된 동안만 불투명도 슬라이더가 잠깁니다. 기본 모드에서는 저장된 수동 불투명도를 사용합니다. 소형 모드로 돌아오면 유리 효과가 다시 켜집니다.
- 유리 효과는 Windows 화면 캡처 API를 사용합니다. 필요한 경우 Windows 허용 창이 표시됩니다. 권한이 없거나 장치가 지원하지 않으면 일반 투명 모드로 표시하고 설정에 이유를 안내합니다. 자기 화면이 반복해서 비치는 것을 막기 위해 효과 사용 중에는 타이머가 스크린샷·화면 공유에서 제외될 수 있습니다. 기본 모드 전환·효과 해제·최소화 시 캡처와 제외 설정을 해제합니다. 화면 잠금·절전 중에도 캡처를 중단합니다.
- 화면은 GPU 메모리에서 처리하고 타이머 영역만 잘라 WPF에 전달합니다. 설정의 **글래스 프레임** 슬라이더로 목표 갱신 빈도를 15~144fps 사이에서 1fps 단위로 조절합니다(기본 60fps). 변경은 즉시 적용되고 재실행 후에도 유지됩니다. 글래스가 꺼져 있으면 슬라이더는 비활성화됩니다. 실제 표시 프레임은 모니터 주사율·캡처 속도·PC 성능에 따라 달라지며 높은 설정은 전력 사용량을 늘립니다. 화면 데이터를 파일에 저장하거나 외부로 전송하지 않습니다. 숫자와 조작 버튼에는 굴절을 적용하지 않습니다.
- 절전 시간도 경과 시간으로 계산합니다. 앱 종료 시 타이머는 종료되며, 재실행 시 마지막 설정 시간으로 대기합니다.
- 설정은 `%LOCALAPPDATA%\FocusTimer\settings.json`에 저장합니다. 별도 서버나 계정을 사용하지 않습니다.

## 개발 및 검증

.NET 10 안정 SDK, Windows, Visual Studio 2022 C++ x64 빌드 도구 및 Windows SDK 10.0.22621 이상이 필요합니다. 앱은 `net10.0-windows`를 대상으로 합니다. `./build.ps1`을 실행하면 네이티브 셰이더/DLL 빌드, 테스트, 독립 실행 배포, UI 검증을 순서대로 수행합니다. 작업 폴더에 준비된 `.cache/dotnet` SDK와 `.cache/nuget` 패키지가 있으면 자동으로 사용합니다. 네이티브 DLL은 정적 C++ 런타임으로 빌드하고 최종 EXE에 함께 포함하므로 사용자는 C++ 런타임을 별도로 설치할 필요가 없습니다.

```powershell
dotnet build FocusTimer/FocusTimer.csproj -c Release
dotnet run --project FocusTimer.Tests/FocusTimer.Tests.csproj -c Release
dotnet run --project FocusTimer/FocusTimer.csproj -c Release -- --verify-ui artifacts/ui
dotnet publish FocusTimer/FocusTimer.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeAllContentForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=embedded -o artifacts/single-file
```

`FocusTimer.Core`는 독립적인 시간 계산, `FocusTimer`는 WPF 화면·Windows 연동, `FocusTimer.Tests`는 외부 테스트 패키지가 필요 없는 계산 검증 프로그램입니다. UI 검증 모드는 사용자 설정을 읽거나 쓰지 않고 `artifacts/ui`에 테마·투명도·배율별 PNG와 결과를 생성합니다.

UI 검증은 실제 Windows 창 생성과 크기 조절 경계, 완료 팝업의 포커스 유지, 최소화 중 완료, 알림 비활성화, 화면 밖 위치 보정도 확인합니다. GPU 셰이더에 자체 체크무늬·흰색·검정·가는 선 패턴을 입력해 두 테마와 세 배율의 24개 결과를 검사합니다. 캡슐 바깥 알파가 0인지, 가장자리 알파가 올바른지, 중앙 대비와 움직이는 배경을 유지하는지 확인하며 PNG는 이 합성 데이터로만 만듭니다.

실제 캡처 검증은 `--verify-ui artifacts/ui --verify-glass-live`로 실행합니다. 앱이 만든 배경 창의 색을 바꿔 유리의 중앙 픽셀과 비교하며 모드 전환·최소화·복원·캡처 제외 해제를 확인합니다. 실제 화면의 이미지는 저장하지 않습니다. 권한 거부는 일반 모드 복구 결과로 별도 보고하며 실제 렌더링 통과로 처리하지 않습니다. 이 검증에는 화면 캡처가 허용되는 데스크톱 세션이 필요합니다.

OS 수준 수동 확인: Windows 설정의 앱 색 모드를 실행 중 변경하기, 실제 모니터 배율 100/150/200%에서 이동·크기 조절, 실제 절전 복귀, 서로 다른 배율의 모니터 연결·해제. 렌더링 배율 검증은 물리 모니터 전환 검증을 대신하지 않습니다.

설치 프로그램, 자동 시작, 트레이 상주, 여러 타이머는 제공하지 않습니다. 배포본은 코드 서명되지 않았습니다.

앱 아이콘은 이 프로젝트에서 만든 파란색 스톱워치 디자인입니다. `tools/create_icon.py`로 16~256px Windows ICO를 다시 만들 수 있습니다(Pillow 필요). 실행 파일과 창·작업 표시줄 모두 같은 아이콘을 사용합니다.

`FocusTimer.Native`의 C++/WinRT 캡처와 Direct3D 11 셰이더는 WPF와 분리된 작업 스레드에서 실행됩니다. 별도 흐림 창을 만들지 않으며, 유리 표면의 알파 마스크와 WPF 클립에 같은 캡슐 형태를 사용합니다. 캡처 장치 오류는 한 번 복구를 시도한 후 실패하면 일반 모드로 돌아갑니다. SDR 색 공간으로 렌더링하므로 HDR 화면의 색 일치는 보장하지 않습니다. 보호된 콘텐츠는 Windows 캡처 정책을 따릅니다.
